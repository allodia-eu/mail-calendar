# Sign in at providers on an earlier draft of the standard

Platforms: all
Bump: patch

> `draft-ietf-mailmaint-oauth-public` named its scopes after protocols (`imap`, `smtp`, `jmap`,
> `caldav`, `carddav`) until `-02` replaced them with `urn:ietf:params:oauth:scope:mail` and its
> siblings. Soverin still advertises the earlier names, and the setup screen offered a sign-in the
> button then refused. Both now ask the same question of the same metadata.

**English**

```
Signing in with your provider now works at providers that follow an earlier version of the sign-in standard, such as Soverin, and the button is no longer offered where signing in cannot work.
```
