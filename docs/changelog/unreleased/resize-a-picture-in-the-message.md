# Resize a picture in the message by dragging a corner

Platforms: all
Bump: minor

> In the shared editor bundle, so one implementation answers a mouse, a trackpad, a pen and a
> finger: Pointer Events are what every host's WebView reports for all four, and a host adding a
> touch path of its own would be a second answer to a settled question. The grips are drawn from
> outside the editor element, because the document the composer emits is read off the editor's own
> tree and chrome inside it would be sent with the message; they are placed from the picture's
> viewport rect and clipped to the editor's box, so a picture scrolled under the toolbar does not
> leave its corners floating over it. A corner drag is projected onto the picture's diagonal, so the
> ratio holds and a movement across it changes nothing, and the width is clamped to what the
> picture's own column can show rather than letting the document carry a size the composer is not
> displaying. A picture in a quoted original is resizable too, and takes its sender's own height
> with it. No keyboard route yet; the gap is recorded in the composer contract.
