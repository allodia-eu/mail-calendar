# Set how often an event repeats

Platforms: all
Bump: minor

> Four controls (a frequency, how many periods to skip, which weekdays, and what ends it) over a
> draft the core hands out and takes back. Which rules the editor may open, what a save should send,
> and which parts of a rule survive an edit that never touched them are one decision in
> `mailcal-account`, not five in the clients: a monthly series pinned to the month's last day keeps
> that when the user only moves its end date, because the client never rebuilds the rule itself.
> A rule the core could not put into a sentence is shown and not offered, which is the same
> judgement `Simple` against `Complex` already makes: an editor seeded from a partial picture
> would write the rest away. Deliberately left out: a control for the monthly and yearly anchor
> ("the second Monday"), which is carried but not editable, and a way to stop a repeat too detailed
> to state. Both are under `docs/calendar.md` → "Known gaps".

**English**

```
Set how often an event repeats: daily, weekly, monthly or yearly, every few days or weeks, on the
weekdays you pick. Choose whether it ends on a date, after a number of times, or never.
```

**Nederlands**

```
Stel in hoe vaak een afspraak zich herhaalt: dagelijks, wekelijks, maandelijks of jaarlijks, om de
zoveel dagen of weken, op de weekdagen die je kiest. Kies of hij stopt op een datum, na een aantal
keer, of nooit.
```

**Deutsch**

```
Legen Sie fest, wie oft sich ein Termin wiederholt: täglich, wöchentlich, monatlich oder jährlich,
alle paar Tage oder Wochen, an den von Ihnen gewählten Wochentagen. Wählen Sie, ob er an einem
Datum, nach einer Anzahl von Malen oder nie endet.
```

date, après un certain nombre de fois, ou jamais.
