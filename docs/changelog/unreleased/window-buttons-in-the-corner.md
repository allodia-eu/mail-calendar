# Window buttons in the corner

Platforms: linux
Bump: patch

> The mail surface's actions bar spans the list and the reading pane, so it is the window's top row
> and the reading pane's header sits a row below it. The controls rode that header, which left close
> a row short of the corner a pointer is thrown at, and the header, having no title widget of its
> own, fell back to the window's title and stood the application's name over the message being read.
> The controls now ride the actions bar, which is a `GtkWindowHandle` so the row drags and
> double-clicks like the caption row it is, and neither that header nor the contacts detail beside it
> names anything. Every other page already carries the controls on its rightmost header, which is
> that page's own top row.

```
The buttons that minimise, maximise and close the window sit in the top corner again, and the application's name no longer stands above the message you are reading.
```
