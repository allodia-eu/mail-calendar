# See and change your subscription in Settings on Windows

Platforms: windows
Bump: minor

> The screen [`allodia_license/purchasing.md`](../../../allodia_license/purchasing.md) says this
> platform owes, now drawn: Settings → Allodia account carries the subscription below the account
> box and only while somebody is signed in. What it draws is what the core answered, `actions`
> decides which buttons exist, and a store's subscription is read-only here, so its button opens
> the page that store sent. Windows sells no store purchase at all, so the one shop is Allodia's
> own checkout and it opens in a browser, never a web view. All four writes are here for the same
> reason Android's are, each only where `actions` permits, and both that change what somebody is
> charged ask first: the cancellation names the day access runs to, and its dismiss button says
> "Keep subscription", because on that question the word "Cancel" is the thing being asked about.
> The switch quotes no price, because what a subscriber is charged is not today's list price; the
> amount comes back from the switch itself and is said afterwards.
> All four writes were driven from this client against production (2026-09-19). The three on an
> existing subscription of Allodia's own: switched period, cancelled, restarted, switched back,
> ending where they began, with the renewal date unmoved throughout and the button set following
> `actions` rather than the card. The fourth, a checkout, was followed through to a completed
> payment, which no client had done before on any platform. The same session also drew the
> store-billed shape, where the service refuses all three writes and the card offers none of them.
> The card re-reads when the window is activated while it is open, because a checkout finishes in a
> browser and the person returns to an answer the app has not asked for again.
