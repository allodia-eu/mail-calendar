# Rename a thread when you reply or forward

Platforms: android, linux
Bump: minor

> The field opens with the subject the core would have sent, derived by the core rather than by
> each client: it is now what goes on the wire, so a client-side `"Re: " + subject` would differ on
> a reply to a reply. An empty field is honoured rather than refilled; only a caller with no
> subject field at all (the MCP surface) still gets the derived one.

**English**

```
Change the subject when replying or forwarding. The field opens with the usual "Re:" or "Fwd:"
and is yours to edit before sending.
```
