## macos, ios

Paste into: App Store Connect (macOS) · App Store Connect (iOS/iPadOS)

**English**

```
When your calendar or address book server moves, the app follows it, and if the new server is run by someone else it asks you first instead of sending your password there.

Every calendar of an account now syncs and can take new events, not only the first, and a refresh with nothing new is quicker.

iCloud and Yahoo calendars and address books now sync, and Fastmail address books now appear.

The app icon now shows how many messages in your inboxes are unread, the same number as the Inbox in the sidebar.

Accepting, declining or answering "maybe" to a meeting now works on Microsoft, Google and other OAuth calendar accounts.

Each calendar now has a colour of its own, across all your accounts, including iCloud and Yahoo calendars that all showed the same colour.

Saving a contact on a Fastmail account works again, and its name keeps the order you typed it in.

A Gmail account with a lot of mail now finishes downloading, continues where it stopped, and keeps receiving new mail meanwhile.

Gmail and Microsoft accounts now show messages as they download, and keep them if a sync is stopped partway.

Google contacts no longer stop updating when the app has gone a week or more without syncing them.

Adding an iCloud account now offers its calendar as well as its address book.

When you add an IMAP account, its messages now appear as they download instead of all at once at the end.

While a new account's mail is downloading, the list no longer says there are no messages.

When a calendar or address book could not be reached, trying again no longer signs in to the mailbox again, so a provider such as Yahoo no longer limits the account's sign-ins.

A message that arrived while another sync was running no longer stays hidden until the next check.
```

## Changes in this release

Engineering commentary, carried over from each fragment. Never pasted into a store.

### A calendar or address book server that moves is followed, and one on another site is asked about first — `calendar-server-moves-asked-first` (macos, ios, windows, android, linux, minor)

> Calendar and contacts connects now start where the server last said the account lives, and
> look the servers up again only when the server says that is gone, never because a network
> was slow or offline. A server found on another site pauses that calendar or address book
> and asks the person whether the move is expected, since a changed DNS record looks the same
> as a provider moving.

### Every calendar of an account syncs, and takes new events — `every-calendar-syncs` (macos, ios, windows, android, linux, minor)

> One connection now serves every calendar an account has. Before, only the first calendar of an
> iCloud, Fastmail or other CalDAV account synced, and creating an event in another one failed. A
> calendar with nothing new is no longer asked for its events, so a refresh with no changes is one
> request however many calendars the account holds. A calendar shared read-only, or a subscribed one
> such as public holidays, is shown but never offered for an event, and a new event goes to the
> calendar the server names its default unless the user chose another.

### iCloud and Yahoo calendars and address books sync, and Fastmail address books appear — `icloud-yahoo-calendar-fastmail-contacts` (macos, ios, windows, android, linux, minor)

> iCloud answers an incremental sync with each changed event's and card's tag but not its
> content, which was read as an empty calendar or address book. Yahoo's calendar and address book
> servers answer no incremental sync, list some events under a doubly encoded address, and refuse a
> request that names no client. Fastmail announces its address books on a second `DAV` header
> line, which was not read. The engine now handles all five, and every request names this app
> with its version.

### Unread count in the dock on Linux — `unread-count-in-the-dock-on-linux` (linux, minor)

> Unity's `LauncherEntry.Update` carries `unified_unread` to the docks that read it (Ubuntu Dock,
> KDE Plasma, Plank), and the count is taken off when the app quits (`docs/app-badge.md`). GNOME
> Shell without a dock extension draws nothing, which is why the note names the docks.

### Unread count on the app icon — `unread-count-on-the-app-icon` (macos, ios, windows, minor)

> The Dock tile, the Home Screen icon and the taskbar button carry `unified_unread`, the number on
> All Accounts › Inbox, and nothing at zero (`docs/app-badge.md`). iOS no longer badges a
> background pass's total: notifications carry no badge, and the pass writes the unread count it
> read. Windows clears the badge as the main window closes.

### Invitations can be answered on Microsoft, Google and OAuth JMAP calendars — `answer-invitations-on-oauth-calendars` (macos, ios, windows, android, linux, patch)

> The app's token-refreshing wrappers for these three calendars did not pass an invitation
> answer, or the lookup of the account's own calendar addresses, to the engine, so accepting,
> declining or answering "maybe" failed as unsupported.

### Every calendar has a colour of its own — `calendar-colours-stay-distinct` (macos, ios, windows, android, linux, patch)

> iCloud sends a calendar's colour with an alpha channel (`#RRGGBBAA`), which was not read, so every
> iCloud calendar fell back to the same blue. Yahoo names one colour for all of an account's
> calendars, and two accounts can name the same one. A server's colour is now kept only while no
> earlier calendar holds its palette hue; the rest take a hue nobody holds, across accounts.

### Contacts save on Fastmail — `fastmail-contacts-save` (macos, ios, windows, android, linux, patch)

> A new contact's name was sent to a JMAP server with its empty parts as `null`, which Fastmail
> refuses, and without saying its name parts are in reading order, so Fastmail stored the surname
> first. The engine now leaves empty parts out and marks the order.

### A large Gmail mailbox finishes downloading, and carries on where it stopped — `gmail-large-mailbox-finishes` (macos, ios, windows, android, linux, patch)

> Google bills a Gmail message fetch at 20 units against 6,000 per user per minute, so the
> engine's twenty-wide fan-out spent a minute's budget in seconds and every pass of a large
> mailbox was refused partway and started again from the top. The engine now paces Gmail under
> that budget, checkpoints a backfill after every page and resumes it from Gmail's page token,
> runs a delta before each page so new mail keeps arriving, and renews the sync lease for as
> long as a pass runs.

### Gmail and Microsoft mail appears as it downloads, and stays when a sync stops partway — `gmail-microsoft-sync-streams` (macos, ios, windows, android, linux, patch)

> The wrappers that refresh a Google or Microsoft token collected a whole pass before passing any
> of it on, so nothing was stored until the last message had arrived, and a pass the server
> stopped partway stored nothing at all. Gmail stops a large pass once its per-minute quota is
> spent, so widening a Gmail account's sync depth to all mail never stored a message. The three
> reconnecting wrappers now share one stream that hands each batch on as it arrives.

### Google contacts keep updating after a week without a sync — `google-contacts-keep-updating` (macos, ios, windows, android, linux, patch)

> Google's People API lets a contacts sync token lapse seven days after the sync that issued it,
> and answers the next request with `400 FAILED_PRECONDITION` and the reason `EXPIRED_SYNC_TOKEN`
> rather than the `410` its Calendar API sends. The engine read that as a conflict, so it sent the
> lapsed token again on every pass and the address book stopped updating for good. It now starts
> that address book over with a full read (allodia-eu/email-calendar-sync-engine#304). An address
> book already stuck recovers at the first sync after the update.

### Setup finds an iCloud calendar — `icloud-calendar-detected` (macos, ios, windows, android, linux, patch)

> Setup looks for a calendar and address book server by asking each candidate address the way a
> calendar app does. It asked with a plain web request, which iCloud's calendar server refuses,
> so an iCloud account was offered its address book but never its calendar.

### A new IMAP account's mail appears as it downloads — `imap-first-sync-streams` (macos, ios, windows, android, linux, patch)

> The wrapper that redials a dropped IMAP connection collected a whole folder pass before passing
> any of it on, so a large inbox stayed empty until its last message had arrived: about 20 seconds
> on a Yahoo inbox of 1,500 messages. Each batch now shows as it arrives.

### A message's attachments can be reached with the keyboard — `linux-attachments-by-keyboard` (linux, patch)

> The attachment rows under an open message sat outside a list, so the keyboard skipped them and
> their Open and Save buttons could be used only with a pointer. They are now a group like every
> other list of rows in the app.

### The calendar no longer redraws itself when nothing in it has changed — `linux-calendar-keeps-its-rows` (linux, patch)

> The agenda, the month and the day and week grid were rebuilt on every input the app received,
> a time-zone check once a minute included, so a press on an event could be lost and keyboard
> focus on a row went with it.

### An error shown as Settings opens is drawn above it — `linux-settings-error-on-top` (linux, patch)

> An error raised in the same moment Settings opens, such as a refused server change asked from
> the calendar or a sign-in that failed during setup, was presented before Settings had drawn,
> and a desktop that stacks windows in the order they appear left it hidden behind Settings.

### A new account's list no longer says it is empty while it downloads — `no-empty-claim-during-first-download` (macos, ios, windows, android, linux, patch)

> While a just-added account's first download ran, the unified inbox said it held no messages from
> the last few months, under a download bar showing hundreds arriving. The list now says nothing
> until that download has ended.

### Retrying a calendar or address book leaves the mailbox alone — `retry-calendar-without-mailbox` (macos, ios, windows, android, linux, patch)

> A calendar or address book that could not be reached beside a working mailbox was retried by
> connecting the whole account again: a new sign-in to the mailbox, a sync of every folder and new
> push connections, on every refresh. Yahoo answers that many sign-ins by limiting the account. Only
> the calendar and address book are now connected again.

### A pushed message waits for a busy folder — `watch-waits-for-busy-folder` (macos, ios, windows, android, linux, patch)

> An IMAP watch's refresh gave up when another sync held the folder, and that sync may have read
> the server before the message landed, so the message stayed unseen until the next change or
> poll. The refresh now waits for the folder, on a task of its own so the watch stays in IDLE
> meanwhile, and changes that arrive while it waits are read by one further refresh.

### The unified Inbox count follows the account Inboxes on Windows — `windows-unified-inbox-count` (windows, patch)

> All Accounts › Inbox was redrawn with the account rows, before the snapshot's sum was read, so
> a sync that moved only the counts left it one snapshot behind the Inboxes under it until
> something else redrew the pane.
