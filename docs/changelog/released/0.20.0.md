# 0.20.0 — 2026-11-27

## macos

Paste into: App Store Connect (macOS)

**English**

```
In a dark app, a message you write now looks as it will when read, and the sun or moon on the formatting bar switches between dark and light.

You can now add a Nextcloud calendar and contacts by entering only your Nextcloud server's address in the manual setup.

Save every attachment of a message at once with Save all, into a folder you choose.

An account's settings now let you enter a separate address book server when its contacts are not on the calendar server.

The composer now shows your message spaced exactly as it is sent, with a blank line above your signature.

The text you write, and the line above a quoted message, now appear in the same colour as when the message is read.

When a calendar or address book server sends the app on to a server your provider's sign-in does not cover, the account now says that this use needs a sign-in of its own, rather than that the server has nothing for the account.

Pressing Enter at the start of your signature now adds a line to your message, and lines typed there are sent as you see them.

A newly added account or shared mailbox shows its folders straight away, while its mail is still downloading.

Answering an invitation to a meeting further ahead than the calendar had loaded no longer fails or sends the reply without recording your answer, and a meeting with a very long ID can now be added to the calendar.

A mail account that signs in with a password can now be given a calendar or address book server in its settings.

A new-mail notification shows the start of the message without empty lines.

The calendar and contacts of an account you signed in to through your provider, other than a Google or Microsoft account, keep working past the first hour, and for every account signed in this way a sign-in the server stops accepting early is renewed without asking you to sign in again.

A calendar, address book or JMAP mail server at an http:// address that is not on this device, or one that sends the app on to such an address, is no longer sent your sign-in, and the app says what clears it.

Replies to plain-text messages no longer end the quoted text with a stray line-ending character.

A stored password or token that the server could never accept, such as an API token containing a space, now asks you to update it, instead of showing the server as unreachable.

“See exactly what we send” now shows every kind of usage statistic the app can send, not only the launch.
```

## Changes in this release

Engineering commentary, carried over from each fragment. Never pasted into a store.

### An open message on Android scrolls as one page, answers from the foot of the screen, and keeps the tabs — `android-reading-view` (android, minor)

> The reading header gives the subject in full, then the sender's name, address and the list's date,
> and one line of recipients by name that opens every address and the full date. Archive, delete and
> the overflow (the sun/moon first in a dark app) move to the top app bar; the answers become large
> buttons at the foot of the screen: the core's default answer (`default_reply_all`), Forward, and a
> chevron with the other answer. The subject, the rest of the conversation, the header and the
> message scroll as one page. The Mail, Calendar and Contacts bar stays while a message is open, and
> Mail returns to the message after a visit to another tab.

### A message is written on the page it will be read on — `composer-dark-page` (macos, ios, windows, android, linux, minor)

> In a dark app the composer and the signature editor draw the message on the reading view's dark
> page, every colour moved by the core's transform for display only, and the toolbar carries the
> reading view's sun/moon switch (`docs/reading-dark-mode.md`, rules 10 to 14).

### Nextcloud from its address alone — `nextcloud-manual-setup` (macos, ios, windows, linux, minor)

> The manual form's account types now come from the core (`manual_setup_kinds`), and a new
> Nextcloud type asks for the server's address alone: the core asks the server whether it is
> Nextcloud (`begin_nextcloud_sign_in_at`) before the browser opens.

### A dot on unread mail in the message list — `phone-unread-dot` (android, minor)

> Users could not tell read from unread on a phone, where the list carried it by weight alone, so
> the dot every desktop layout already drew now leads every row (`docs/avatars.md`), in the row's
> start padding so the text keeps its width.

### Save all attachments at once — `save-all-attachments` (macos, ios, windows, android, linux, minor)

> The core writes every file into the folder (`save_all_attachments`), naming each from the
> sender's name made safe for a filesystem and numbering a name the folder already holds, so
> nothing there is written over. All or nothing: a failed write removes what it wrote. iPhone and
> iPad hand the files to one share sheet; Android copies them into a folder the person picked.
> Offered from two files up; with one, Save already does it.

### A dot on unread mail, and more of each message, in the list on iPhone and iPad — `touch-mail-rows` (ios, minor)

> Users could not tell read from unread on a phone, where the list carried it by weight alone, so
> the dot every desktop layout already drew now leads every row (`docs/avatars.md`), in the list's
> leading margin. The row takes Apple Mail's order: sender and date, the subject, then two lines of
> the message, with a conversation's chevron after the date. The core now flattens a preview's line
> breaks, which cut a snippet off at its greeting.

### The actions over an open message move to the top bar on iPhone and iPad, and the tabs stay — `touch-reading-actions` (ios, minor)

> Seven bordered buttons in a band under the back button become the navigation bar's own glass
> groups: archive and delete, the default answer with a chevron for the others, and the More menu.
> The default answer is reply-all when it would reach someone a plain reply does not, decided by the
> core (`default_reply_all`). The tab bar now stays while a message is open, and each tab keeps its
> place, so a trip to the calendar to check a proposed time returns to the message.

### A clearer header over an open message on iPhone and iPad — `touch-reading-header` (ios, minor)

> The header cut the subject at two lines beside the avatar and drew the sender and every recipient
> as one `Name <address>` string in caption type. The subject is now the page's title, never cut
> short; the sender is named with their address beneath, which is what exposes a borrowed name; the
> recipients are named on one line that opens the details with every address and the full date. The
> date in the header is the list's relative label (`docs/timestamps.md`). The core now sends names
> and addresses apart (`MailPerson`), so no client splits the joined strings.

### Drag on the Windows calendar grid to create, move and resize events — `windows-calendar-drag-create` (windows, minor)

> A mouse or touchpad click-drag on empty grid draws a new slot and opens the editor on it; on your
> own event it moves the event, or resizes it from its top or bottom edge, asking *This event · All
> events* first for a repeating one. On a touch screen a finger or pen held still for a moment does
> the same. The other platforms already do this.

### Address book server in an account's settings — `address-book-server-field` (macos, ios, windows, android, linux, patch)

> An account whose contacts are served by its calendar server now shows an empty address book
> server on its page (`AccountConfig::endpoint_form`), so a provider's own CardDAV server can be
> entered without setting the account up again. Left empty, the calendar server goes on serving
> the contacts, and the page says so.

### The composer spaces a message as it is sent — `composer-spacing-as-sent` (macos, ios, windows, android, linux, patch)

> The editor's own margins above the signature and the quote, and under the quote's attribution,
> are gone: the renderer never sent them. A new message and a reply open with a real blank line
> above the signature, and between it and a quote; a drafted reply keeps one.

### The composer draws a message's text in the colour it is read in — `composer-text-as-read` (macos, ios, windows, android, patch)

> The shared editor's light page takes the reading view's ink, and the quote attribution, sent
> without a colour of its own, is drawn in it rather than in grey (`docs/reading-dark-mode.md`,
> rule 10). The dark page itself is `composer-dark-page.md`'s.

### A calendar that leads past the provider's sign-in says so — `dav-hop-needs-own-sign-in` (macos, ios, windows, android, linux, patch)

> A calendar or address book whose discovery leads to a host the account's grant may not take
> its token to (`docs/mail-oauth.md` rule 10) now reports that the use needs a sign-in of its own
> (`AccountError::DavNeedsOwnSignIn`), rather than that the server has none for the account.

### Enter in the signature's first line starts a line of the message — `enter-in-signature-line` (macos, ios, windows, android, linux, patch)

> Enter in a line the signature or a quoted body holds directly splits that line inside the region
> (`region_lines.ts`) rather than leaving the engine to split the region and copy its class: each
> copy went out as one more signature under its own `-- `, or as a quoted half that was not sent.
> Enter at the very start of the signature opens a line of the message above it.

### Folders show before their mail has downloaded — `folders-show-before-mail` (macos, ios, windows, android, linux, patch)

> A sync's mid-pass updates carried the folder pane over from the last full rebuild, so a new
> account's or shared mailbox's folders appeared only once every folder's mail was in. The core now
> redraws the pane as soon as the engine has stored the folder list, when the tree changed.

### Answering an invitation to a meeting far ahead works on a CalDAV calendar — `invitation-answer-on-stored-meeting` (macos, ios, windows, android, linux, patch)

> A meeting the core stores before answering is put at the address the calendar adapter names
> for its `UID` (`new_event_id`), and read back from there. The core's own spelling encoded an `@`
> that servers list bare, so the read-back missed and fell back to the day scan, which sees only
> the expanded window: beyond it the server route failed and the iMIP route sent the reply with
> no answer stored. It also kept a `UID` too long to be a resource name, which some servers refuse.

### Linux draws the writing area of every new message — `linux-composer-blank-editor` (linux, patch)

> WebKitGTK's hardware-accelerated renderer never paints a view whose page is laid out while the
> view has no height, and resizing it afterwards does not recover it (WebKit bug 332660). The
> composer's editor had no height until the column first measured its visible part, and from the
> second composer on the page loads before that, because the content filter it waits for is
> already compiled; a first composer did so about one time in four. The editor is now given its
> minimum height when the column takes it.

### Calendar server for a mailbox in an account's settings — `new-calendar-server-field` (macos, ios, windows, android, linux, patch)

> A password account with no calendar or address book server now shows both empty on its page
> (`AccountConfig::endpoint_form`). A server typed there is tried with the account's login and
> password, and once it connects its use is switched on, so a mailbox set up without a calendar
> no longer has to be set up again to get one.

### A new-mail notification shows the start of the message as one run of text — `notification-preview-one-line` (macos, ios, windows, android, linux, patch)

> The notification carried the provider's snippet with its own line breaks, so it could show a
> greeting and an empty line. It now goes through the same `preview_line` the list rows use.

### An account signed in through its provider keeps its calendar and contacts — `oauth-sign-in-renewed` (macos, ios, windows, android, linux, patch)

> The calendar and address book of an account signed in through its provider's own OAuth
> sign-in, other than Google and Microsoft (CalDAV and CardDAV over the grant's token), were
> built over the token minted at connect, so they stopped an hour later, when it expired. Every
> adapter of an account now asks the account's one credential source for the token on each
> request, and a token a server refuses before its stated expiry is renewed once, through the
> same single-flight refresh, before the request is sent again; only a grant that is gone still
> asks for a sign-in.

### A server at a plaintext address is no longer sent a sign-in — `plaintext-server-not-sent-sign-in` (macos, ios, windows, android, linux, patch)

> The engine sends no credential over plaintext to a server off this device, so a calendar,
> address book or JMAP server at an `http://` address, or one that leads there, now fails its
> connect as `AccountError::InsecureServer`, with the engine's cause (`PlaintextAddress` or
> `LedToPlaintext`). The app says so on every surface (setup, the account's page, the
> `InsecureServer` notice, the use problems) rather than as a refused sign-in or an outage, and
> says what clears it (`docs/provider-oauth.md` rule 12).

### A reply to a plain-text message carries clean line endings — `quote-plain-line-endings` (macos, ios, windows, android, linux, patch)

> A plain-text original keeps the CRLF its MIME part was written in. The editor now reads it on any
> line ending (`plain_text.ts`) and holds it in `\n` alone (`quote.ts`), so neither half of a reply
> carries a bare carriage return.

### A stored sign-in the server could never accept asks to be updated — `stored-secret-cannot-be-presented` (macos, ios, windows, android, linux, patch)

> The engine refuses, before sending anything, a stored password or token its protocol cannot
> carry (a Basic username holding `:`, a line break in an IMAP password, an API token a header
> cannot carry). The first connect of an account that stores its secret now reads that as a
> refused sign-in (`AccountError::SigninRejected`, `docs/provider-oauth.md` rule 12). An API
> token a header cannot carry failed every request as `Retryable` before, which read as a server
> that could not be reached; a Basic username holding `:` went out and was refused, which already
> asked for a new sign-in.

### The usage statistics preview shows every kind of event — `usage-statistics-preview-every-event` (macos, ios, windows, android, linux, patch)

> The core builds the preview from one event of every kind, each feature and each protocol on an
> event of its own, and the device's own settings, so a person sees every label before opting in.
> Every client draws the core's string unchanged; no client code moved.
