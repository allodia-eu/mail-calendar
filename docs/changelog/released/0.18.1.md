## Changes in this release

Engineering commentary, carried over from each fragment. Never pasted into a store.

### Windows opens again when the app follows the system language — `windows-opens-with-system-language` (windows, patch)

> 0.18.0 handed "follow the system" to the Windows App SDK's language override as the empty string,
> which that setter refuses in both build shapes. The refusal came from `App`'s constructor, inside
> `Application.Start`, so every launch without a stored language choice ended before the window
> existed (0xC000027B in Microsoft.UI.Xaml.dll). A packaged build now clears the package's own
> `Windows.Globalization` override instead, and an unpackaged one sets nothing. The UI suites gain a
> first-run launch with no language stored; every other launch pins English, which is why none
> reached this path.
