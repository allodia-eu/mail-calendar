## macos

**English**

```
If the app closes while a message is being sent, it is no longer lost or sent twice: it is sent at the next start, or the Outbox asks whether it arrived. A message the server refused now stays in the Outbox, to send again, edit or discard.

You can now drag a folder into another folder or onto its account, and drag messages onto a folder to move them there.

Add links to a message with the new Link button, or type an address and press Space. Web addresses in messages and event notes are now clickable.

You can now make, rename, move and delete folders from the folder pane, even offline.

Contacts from a Microsoft account appear in the app, and you can add and edit them; on a work or school account, your colleagues are suggested as you address a message.

You can now move a message to any folder from its menu.

An open message can now be printed, from the menu at the end of the reading toolbar.

Connect a mail account by signing in with your provider, where your provider supports it, instead of storing a password. Where it doesn't, the password field is still there, and the setup screen now says which of the two your provider actually offers.

When a mail provider asks the app to slow down, the status line below your messages now says so, and says when syncing continues.

The message you are writing is now kept in your Drafts folder while you write it, so your other devices see it and nothing is lost if you move to another message or close the app; open a draft to carry on where you left off.

Account setup now has a Back button that returns from the found settings or the manual form to the email address step.

Calendars are grouped under each account's email address instead of an internal name.

Your contacts now appear even when an address book holds a contact with no name or email address, such as a saved phone number.

On accounts that connect over JMAP, people in Cc and Bcc now receive your message, and your replies stay in the recipients' conversation.

Editing a message in the Outbox now moves it back to Drafts with its attachments, and sending again a message that may already have arrived asks first.

Folders that only hold other folders, such as Gmail's [Gmail], are no longer offered as a place to move mail or to watch for new mail.

Signing in with a Microsoft account no longer asks for permissions the app does not use.

On IMAP accounts, Save to Sent now files the copy of a sent message that could not be saved in your Sent folder.

A message that cannot be sent yet now appears in the Outbox straight away, even while the mail server is not answering.

Every folder of an IMAP or Microsoft account now syncs in the background within the sync depth you chose, not only the Inbox and the standard folders; on push, the folders not watched are checked every 15 minutes.
```

## Changes in this release

Engineering commentary, carried over from each fragment. Never pasted into a store.

### A send survives the app closing, and a refused one is kept — `a-send-survives-the-app-closing` (macos, ios, windows, android, linux, minor)

> A send cut off by the app ending stayed "Sending" for good, and one the server refused left the
> Outbox and was gone. The engine now records the point where the server could act on a message:
> at start-up a send cut off before it is sent again, one cut off after it asks the user whether it
> arrived, and a refused send stays in the Outbox until the user acts. Every Outbox step is logged.

### Drag folders and messages onto a folder — `drag-folders-and-messages-onto-a-folder` (macos, windows, linux, minor)

> A folder dragged onto another folder moves inside it, onto its account's row moves to the top;
> messages, or the selection they belong to, dragged onto a folder move there. Neither crosses
> accounts. The iPad drags too, but its notes go out with the iPhone's, which does not.

### Every account in Settings on Linux — `every-account-in-settings-on-linux` (linux, minor)

> Settings → Accounts listed mail accounts only, each as one card. It now lists every account and
> opens a page per account with its uses, links, mail settings and removal.

### Links in messages and events — `links-in-messages-and-events` (macos, ios, windows, android, linux, minor)

> Two halves. Writing: a Link button (and Ctrl/Cmd+K) in the shared editor makes, changes and
> removes a link, and an address typed into the body becomes one when the word ends with a space
> or Enter. The target is `http`, `https` or `mailto` only and is checked again in Rust on submit;
> the plain-text part carries `words <address>`. Reading: web and mail addresses written as text
> become links in HTML bodies (a pass over the sanitiser's output in the core), in plain-text
> bodies, in event notes and in an invitation's description (native text built from the core's
> runs). Every link opens through `should_open_external_link`. Bare domains and bare email
> addresses are not linked.

### Make, rename, move and delete folders — `make-rename-move-and-delete-folders` (macos, ios, windows, android, linux, minor)

> Folder changes go through the engine's outbox: one made offline is drawn at once, marked as
> waiting, and sent on reconnect, after the engine has checked the folder is still where the user
> saw it. Delete puts a folder in Trash; deleting it from Trash removes it for good. Dragging is
> its own fragment, because it reaches only the platforms that drag.

### Contacts from a Microsoft account — `microsoft-contacts` (macos, ios, windows, android, linux, minor)

> A Microsoft account requested the contact scopes at sign-in but bound no contacts adapter, so its
> Contacts list stayed empty. The dial now binds one Graph adapter per personal contacts folder and
> one for the tenant directory, so saved Outlook contacts appear, can be added and edited, and
> colleagues on a work or school account feed recipient suggestions and sender pictures.

### Move mail to a folder from its menu — `move-mail-to-a-folder-from-its-menu` (macos, ios, windows, android, linux, minor)

> A message's row menu gains Move to folder…, which lists the folders of its account that take
> mail. On the desktops and the iPad and iPhone it moves the selection when the row is in it; on
> Android, where a long press starts a selection, it is on the row's own menu and moves that one
> message. Linux message rows now open their menu on a right click as well as from the button.

### Print a message — `print-a-message` (macos, ios, windows, android, linux, minor)

> The reading view's overflow menu gains Print, below Save as .eml. The page is built once in the
> core (`render_print_document`): the subject and the From, To, Cc, Bcc and Sent lines the reading
> header draws, as escaped text, above the sanitised body, inside the same strict-CSP document the
> reading view loads, so a printout loads a remote image only when the reader already did. Each
> client lays it out in a second web view carrying the reading host's gates and hands that to the
> platform's print dialog (`docs/reading-actions.md`).

### Sign in to a mail account instead of typing a password — `sign-in-to-a-mail-account-instead-of-typing-a-password` (macos, ios, windows, android, linux, minor)

> The setup screen asks the mail server what it accepts before it draws a field, so which
> credential a person is asked for is the server's answer rather than a guess. Three answers,
> because they are three screens: sign in with the provider, a line saying the provider admits
> only applications it registered in advance, or the password form as it always was. The middle
> one is the point: showing one bare password form for a provider whose sign-in is simply
> closed to us leaves someone wondering why the button their colleague has is missing.
> An issuer is only ever taken from the provider describing itself over HTTPS, never from a
> third-party database and never from an untrusted hop, and the endpoints come from that
> issuer's own metadata. An account that signs in stores no password anywhere, including for
> its calendar. `Platforms:` names the clients that draw the surface: the core decides for every
> client, and one that does not draw it yet carries the answer no further than the binding
> (`docs/mail-oauth.md` → Known gaps).

### The app says when a sync is paused, and when it continues — `the-app-says-when-a-sync-is-paused` (macos, ios, windows, android, linux, minor)

> A rate limit had become invisible. The previous change stopped it reading as an outage, which
> was right, but left the account looking entirely healthy while no mail arrived for it, and the
> user with no way to tell a paused sync from a quiet mailbox. The status line the footer already
> draws now says "Sync paused" in place of the background-sync note, with the account and when
> syncing continues behind a hover on a computer, and spelled out in the line itself on a phone,
> which has no hover. The wait is the server's own and is stated as an approximation, rounded up
> to whole minutes so it is never promised early; about two Gmail refusals in three name no
> window at all, and those say "shortly" rather than inventing a figure. The notice takes no row
> of its own, so nothing moves under the pointer, and it clears itself the moment the wait
> elapses. The sentence is the accessibility name on every platform, so a screen reader hears the
> wait and not just the label.

### The message you are writing is kept on the server — `the-message-you-are-writing-is-kept-on-the-server` (macos, ios, windows, android, linux, minor)

> The composer held the only copy of a half-written message: closing it, or losing the app, lost
> what was there. It now stores the message in the account's Drafts folder once the composer has
> been idle for the core's interval, and at once on "Save as draft". Each save supersedes the
> last rather than adding to it, keyed on what the provider answered with, so the user's other
> devices and their webmail see one message being written. Leaving the composer, by a click
> elsewhere, a closed window or back, saves it there without asking; Discard is the one way to
> throw it away. A row in Drafts opens back into the
> composer it was written in, holding its files, and saves over that copy; sending takes the
> stored copy away, and a send that failed leaves it, being the only one left.

### A way back from account setup — `a-way-back-from-account-setup` (macos, ios, windows, patch)

> The detected-settings and manual steps of account setup had no way back to the address step on
> Apple or Windows. Android already stepped back with the system Back and Linux with a button.

### Add an account in a dialog on Windows — `add-an-account-in-a-dialog-on-windows` (windows, patch)

> Adding a second account replaced the whole window with the setup form. It now opens in a dialog
> over the mailbox; the first account is still set up in the window, which has nothing else to show.

### Calendar groups named by address — `calendar-groups-named-by-address` (macos, ios, android, patch)

> The calendar manager, the calendar picker and the default-calendar setting headed each account's
> calendars with its internal id (`address@provider-host`). Every calendar row now carries the
> account's address, and every client heads its groups with it; Linux and Windows already showed
> the address, through the account switcher's list, which accounts without mail are no longer in.

### Contacts appear when an address book holds one with no name — `contacts-with-no-name` (macos, ios, windows, android, linux, patch)

> A contact with neither a name nor an email address, such as a saved phone number, failed the
> engine's people write, so a contacts sync returned an error and the Contacts list stayed as it
> was, empty on a new install. Fixed in the engine
> (allodia-eu/email-calendar-sync-engine#251); this change moves the pin.

### Deliver mail sent over JMAP to its Cc and Bcc recipients — `deliver-jmap-mail-to-cc-and-bcc` (macos, ios, windows, android, linux, patch)

> The engine built a JMAP send from its To recipients alone: Cc and Bcc were never written into the
> message or its delivery list, and a reply carried no In-Reply-To or References. It now carries all
> of them, with Bcc kept on the sender's copy only. Fixed in the engine
> (allodia-eu/email-calendar-sync-engine#239); this change moves the pin.

### Editing a message in the Outbox keeps its files — `edit-from-the-outbox-keeps-files` (macos, ios, windows, android, linux, patch)

> Edit on a queued send handed the composer the recipients, subject and text only, so files and a
> reply's threading were dropped. It now moves the message back into Drafts first and opens the
> composer on that draft holding every file. A sent message also no longer leaves a copy in Drafts
> when the server refuses it: the Outbox keeps it. Sending again a message whose delivery was not
> confirmed now asks first.

### Escape closes a dialog on Linux — `escape-closes-a-dialog-on-linux` (linux, patch)

> Every Linux dialog is a plain GTK window, which binds no key to closing. Escape now does what
> the close button does.

### The folder pane keeps its place on Windows — `folder-pane-keeps-its-place` (windows, patch)

> Every change to an unread count took each account's rows out of the pane and put them back
> collapsed, so a pane scrolled below an open subfolder moved by a few rows a moment later.

### Folders that only hold folders — `folders-that-only-hold-folders` (macos, ios, windows, android, linux, patch)

> An IMAP folder that exists only to hold other folders (Gmail's `[Gmail]`, a parent created for
> its children) was synced on every pass and failed, took dropped mail the server then refused,
> and was offered for push.

### The manual form shows the ports it dials — `manual-form-shows-the-ports-it-dials` (windows, patch)

> Two faults in the manual form's Port fields. Reopening account setup kept the previous
> account's detected ports on screen while the form dialled the standard ones. And the port
> followed the security picker only once: the form's own write came back as TextChanged after
> it had returned and was taken for the person typing a port.

### Microsoft sign-in asks for less — `microsoft-sign-in-asks-for-less` (macos, ios, windows, android, linux, patch)

> Drops `openid`, `profile` and `email` from the Graph request: nothing read the ID token they
> bought. An organisation that approves each permission by hand now reviews seven, each with a call
> site named in `docs/provider-oauth.md`. Existing grants keep what they hold; nobody is asked to
> sign in again.

### Save to Sent on IMAP accounts — `save-to-sent-on-imap` (macos, ios, windows, android, linux, patch)

> The IMAP connection wrapper did not forward the repair that files a delivered message's copy in
> Sent, so on an IMAP account "Save to Sent" always failed.

### A queued message appears in the Outbox at once — `show-queued-send-at-once` (macos, ios, windows, android, linux, patch)

> The Outbox rides the mailbox-list snapshot, and after a send that queued, that snapshot was
> republished only by the sync that followed. A server that accepts the connection and then
> answers nothing holds that sync indefinitely, so the hint said "Waiting to send." with no Outbox
> to look in. The list is now republished from the store as soon as a send or a drain pass has an
> outcome. Each send attempt is also logged as it starts.

### Sync every folder, not only the ones the server gives a role — `sync-every-folder` (macos, ios, windows, android, linux, patch)

> An IMAP or Microsoft account bound a provider only to the Inbox and the folders the server tagged
> Sent, Drafts, Trash, Archive or Junk, so every other folder synced once, when it was opened, and
> no pass named it again. A server that tags its Archive `\All` (a real one does) lost that folder
> too, which is where archiving files mail. The dial now binds every folder the account lists
> except `\Flagged` and `\Important`, which are views of mail filed elsewhere; a pass binds and
> syncs a folder listed since the account connected; and an account on push also runs a full pass
> every 15 minutes, because a watch covers only the folders it names.
